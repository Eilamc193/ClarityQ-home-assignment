1. OVERVIEW
-----------
The ICP Demo Dashboard is a standalone web prototype that demonstrates how
an AI-native SDR would operate at ClarityQ. Rather than submitting a static
document, this tool shows a repeatable, automated pipeline-building workflow —
from ICP discovery to hyper-personalized outreach — powered by Claude AI and
Hunter.io email enrichment.

The prototype is built with React (Vite) + Claude API (claude-sonnet-4-6) +
Hunter.io API.

Data source approach: Hybrid — curated/hardcoded company and persona data
(manually researched) combined with live email lookup via Hunter.io's free tier
(25 searches/month). Emails are pre-generated via Claude and cached locally;
Claude API is the live fallback.


2. PROBLEM STATEMENT
--------------------
Traditional SDR workflows are manual, slow, and produce generic outreach:
  - Research per prospect: 20-40 min manually
  - Emails are copy-paste templates with light personalization
  - No live signal tracking to prioritize hot accounts
  - Pipeline visibility is disconnected from outreach activity

ClarityQ's core use case is not the boardroom. Boards have analysts.
The real pain lives in the morning coffee moment:

  A Head of Product or Head of Growth opens their laptop at 8 AM. They see
  a ROAS anomaly, a drop in LTV cohort, or a funnel step that collapsed
  overnight. They need to understand it in 10 seconds — not file a ticket,
  not wait two days for an analyst, not toggle between three dashboards.

  ClarityQ is the instrument that lets them say "I know exactly why that
  happened" before the 9 AM standup.

This framing shapes every targeting and messaging decision in this pipeline:
  - We target operators who own a metric daily (Head of, VP-level), not
    CEOs who receive reporting from above.
  - We lead with the anomaly-resolution moment, not BI infrastructure.
  - We connect fragmented stacks (e.g., Telehealth consultation logs +
    Snowflake purchase data, AppsFlyer attribution + app store conversion)
    so the operator sees one true picture — immediately.

ClarityQ needs an SDR who treats pipeline building as a growth engineering
problem — automating the repetitive, and spending human time only on judgment
and relationship.


3. TARGET USER

Primary: The candidate (demonstrating workflow to ClarityQ hiring team)
Secondary: Any AI-native SDR running outbound at a B2B SaaS startup

    Both tiers feel the anomaly-resolution pain ClarityQ solves.

  1,001–5,000 employees:
    → Director + Head of (Product, Marketing, UA, Growth,
                          Data Science, BI, Revenue Ops)
    VPs are too senior — insulated by reports and dashboards.
    Directors and Heads own a specific function and feel every data gap.

  5,000+ employees:
    → Director, Senior Manager,
      Head of (Product, Marketing, UA, Growth,
               Data Science, BI, Revenue Ops)
    Team Leads are too junior (no budget authority) — avoid.
    Target the layer that owns a P&L or channel metric directly.

  Key principles:
    - CEOs are only reachable and relevant below ~100 employees
    - VPs own budget authority up to ~1,000 employees
    - Heads/Directors own budget authority from ~250–5,000 employees
    - Team Leads have no budget — wrong entry point for ClarityQ
    - Lead with the anomaly-resolution moment for all tiers, not BI infra

MODULE 4: AI Email Composer
----------------------------
Purpose: Generate hyper-personalized outreach emails, not templates

Trigger: User clicks "Draft Email" from a persona card (Module 2)

Email types supported:
  1. Cold Intro  — lead with a specific signal, one-line value prop, soft CTA
  2. Follow-up   — Day 5, different angle, references a new trigger,
                   explicitly avoids "just following up"
  3. Post-Rejection — graceful, under 60 words, plant a seed for future timing

Tone selector (3 options):
  - Concise      — Under 100 words, every sentence earns its place
  - Conversational — Warm and human, like a sharp colleague reaching out
  - Direct       — Confident and straight to the point, no hedging

Total combinations: 3 email types × 3 tones = 9 emails per persona

Output format (JSON, from Claude or cache):
  {
    "subject": "compelling subject line",
    "body": "full email body with greeting and sign-off",
    "personalization_notes": ["specific thing personalized 1", "..."]
  }

Email generation workflow (two-path):

  PATH A — Cache hit (preferred, zero API cost):
    1. EmailComposer calls getCachedEmail(personaId, emailType, tone)
    2. If found → simulates a realistic 0.9–1.5s delay (UX authenticity)
    3. Returns the pre-generated email object
    4. Cache covers all 12 non-AppsFlyer personas (108 emails total)
       Key: emailCache[personaId][emailType][tone]

  PATH B — Live Claude API fallback:
    1. Triggered when persona is not in cache (e.g. AppsFlyer personas)
    2. Requires VITE_ANTHROPIC_API_KEY in .env
    3. Calls Anthropic API: POST https://api.anthropic.com/v1/messages
       Model: claude-sonnet-4-6 | Max tokens: 1024
    4. System prompt: SDR context at ClarityQ, value prop, tone + type rules,
       output format, outreach principles (no buzzwords, ≥2 specific signals)
    5. User prompt: prospect name/title/company/stack + top 3 buying signals +
       email type instruction + tone instruction
    6. Response: JSON extracted even if Claude wraps in markdown backticks
    7. Displayed identically to cached result

Claude prompt strategy:
  - System prompt encodes: SDR identity, ClarityQ one-line value prop, the
    pain solved (analyst bottleneck), 5 outreach principles, output JSON schema
  - User prompt encodes: prospect context (name, title, company, industry,
    headcount, tools used, description) + signal bullets + type/tone instructions
  - Result is deterministic in cache, generative for new personas

One-click actions after generation:
  - Regenerate (new live API call for a different angle)
  - Copy to clipboard
  - Add to Pipeline → creates card in Module 5


MODULE 5: Pipeline Board
-------------------------
Purpose: Track outreach status across all prospects in one Kanban view

Columns (7 stages):
  Identified → Researched → Email Drafted → Sent → Replied → Meeting Booked
                                                  → Nurture

Stage color coding:
  Identified     → Gray
  Researched     → Blue
  Email Drafted  → Amber
  Sent           → Indigo
  Replied        → Cyan
  Meeting Booked → Emerald
  Nurture        → Orange

Prospect card data:
  - Name, title, company name, avatar initials
  - Current stage badge
  - Days since added / last touched (auto-calculated)
  - Stage transition buttons: advance or move to Nurture
  - Remove button

Pipeline behavior:
  - addProspect: de-duplicates by personaId — can't add same persona twice
  - moveProspect: updates stage + lastTouchedAt timestamp
  - When moved to Replied, Meeting Booked, or Nurture → triggers A/B log modal

State management:
  - Zustand store (usePipelineStore) with localStorage persistence
  - Key: 'ghd-pipeline'
  - No backend required — all state is browser-local


MODULE 6: A/B Testing & Response Tracker
-----------------------------------------
Purpose: Systematically capture outreach outcomes and surface patterns that
improve future messaging, persona targeting, and channel selection.

HOW IT WORKS:
  When a prospect advances to "Replied", "Meeting Booked", or "Nurture" on
  the Pipeline Board, the dashboard triggers an A/B Response Log Modal.
  The SDR fills in outcome details. All data is stored in Zustand +
  localStorage and aggregated live into the Insights panel.

A/B RESPONSE LOG MODAL — fields captured:
  ┌─────────────────────┬────────────────────────────────────────────────────┐
  │ Field               │ Values                                             │
  ├─────────────────────┼────────────────────────────────────────────────────┤
  │ Outcome             │ Positive reply / Meeting booked / Rejection /      │
  │                     │ No response / Bounce                               │
  │ Persona title       │ VP Product / Head of Data / CEO/CBO / VP Growth /  │
  │                     │ Other (free text)                                  │
  │ Platform used       │ Email / LinkedIn DM / Phone call / Other           │
  │ Email type          │ Cold Intro / Follow-up / Post-rejection            │
  │ Tone used           │ Concise / Conversational / Direct                  │
  │ Subject line        │ Free text (auto-suggested from drafted email)      │
  │ Email snippet       │ First 2 lines (auto-suggested from drafted email)  │
  │ Days to response    │ Numeric (0 = no response)                          │
  │ Notes               │ Free text (e.g. "said budget frozen until Q3")     │
  └─────────────────────┴────────────────────────────────────────────────────┘

A/B STORE (useABStore):
  - Zustand store with localStorage persistence (key: 'ghd-ab-tracker')
  - Pre-seeded with 23 mock baseline entries (MOCK_SEED array in useABStore.js)
  - logResponse(entry) appends new entries with timestamp
  - getInsights() computes all metrics live from the full responses array

COMPUTED INSIGHTS:
  Win definition: outcome === 'positive_reply' OR 'meeting_booked'
  Win Rate = wins / total × 100 (rounded to integer %)

  1. Win Rate by Tone (bar chart)
     Groups: Concise / Conversational / Direct
     → Which tone drives the most positive replies?

  2. Win Rate by Persona Title (bar chart)
     Groups: Head of Data / VP Product / CEO/CBO / VP Growth
     → Which role is most responsive to ClarityQ's value prop?

  3. Win Rate by Platform (bar chart + avg days to reply)
     Groups: Email / LinkedIn DM / Phone
     → Where do conversations actually start?

  4. Win Rate by Email Type (bar chart)
     Groups: Cold Intro / Follow-up / Post-Rejection
     → Does persistence pay off? Is Day 5 follow-up worth it?

  5. Top Performing Emails (table)
     Emails with ≥1 win, sorted by win rate descending, top 3 shown
     Columns: Subject | Snippet | Tone | Type | Persona title | Win rate

MOCK BASELINE DESIGN INTENT (23 seeded entries):
  The seed is designed to surface these insights in the demo:
  - Concise tone outperforms Direct, which outperforms Conversational
  - Head of Data is the highest-converting persona (2.3x vs VP Growth)
  - LinkedIn DM outperforms Email for first touch
  - Day-5 follow-up conversion nearly matches cold intro
  - Post-rejection re-engagement converts when given enough time (14 days)

  Real logged data appends to the seed and gradually shifts the numbers.

7. USER FLOW (end-to-end demo path)
-------------------------------------
1. Open dashboard at localhost:5173 → ICP Scanner tab
2. View 5 ranked target accounts, ICP scores, tools, and signals
3. Click a company (e.g., Play Perfect) → Persona Finder opens
4. Review 2-4 persona cards with pre-loaded "Why target" rationales
5. Click "Find Email" on a persona → Hunter.io live lookup runs
   - Email + confidence score displayed (or LinkedIn DM fallback for AppsFlyer)
6. Click "Draft Email" → Email Composer opens
7. Select: Email type (Cold / Follow-up / Rejection) + Tone
8. Click Generate → Cache hit returns email in 0.9–1.5s with personalization notes
   (or live Claude API call for uncached personas, ~3s)
9. Review subject, body, personalization notes — edit if needed
10. Click "Add to Pipeline" → card appears in Pipeline Board under "Identified"
11. Navigate to Pipeline Board → see all prospects in Kanban view
12. Advance card to "Email Drafted" → "Sent" → "Replied"
13. On moving to "Replied" → A/B Response Log Modal appears
14. Log outcome, platform, tone, email type, days to response, notes
15. Navigate to A/B Insights → live charts update with logged data on top of
    the 23 mock baseline entries
16. Top performing emails surface in the insights table

AppsFlyer special path:
  - Domain opted out of Hunter.io → "Find Email" shows "Domain opted out" state
  - UI offers "Connect on LinkedIn" link instead
  - No email cache exists for AppsFlyer personas (cache is domain-lookup gated)
  - Email generation falls back to live Claude API (requires VITE_ANTHROPIC_API_KEY)


8. ARCHITECTURE — DATA FLOW
----------------------------

ICP SCORING (static, per company):
  companies.js → icpBreakdown[] array → ICP score shown in ICPScanner.jsx

PERSONA EMAIL LOOKUP (on demand):
  PersonaFinder.jsx → hunter.js:findEmail({ domain, name })
    → GET https://api.hunter.io/v2/email-finder?domain=...&first_name=...&last_name=...&api_key=...
    → returns { email, confidence } or error string

EMAIL GENERATION (cache-first):
  EmailComposer.jsx → claude.js:generateEmail({ prospect, company, emailType, tone })
    → emailCache.js:getCachedEmail(personaId, emailType, tone)
      → HIT: return cached JSON after simulated delay
      → MISS: fetch('https://api.anthropic.com/v1/messages', ...)
               with system + user prompt → parse JSON from response

PIPELINE STATE (persistent):
  PipelineBoard.jsx ↔ usePipelineStore (Zustand + localStorage 'ghd-pipeline')
  addProspect / moveProspect / removeProspect — all operations sync to storage

A/B LOGGING (persistent):
  ABResponseModal.jsx → useABStore:logResponse(entry) → appended to responses[]
  ABInsights.jsx ← useABStore:getInsights() — computed live on each render

  persona emails were verified during build; live lookups during demo consume
  quota sparingly. A lookup is only triggered when the user clicks "Find Email."

- Claude API browser access: the app calls the Anthropic API directly from
  the browser (using the anthropic-dangerous-direct-browser-access header).
  This is acceptable for a demo prototype; production would proxy through a
  backend to keep the key secret.

- Pipeline state and A/B data are localStorage-only. Clearing browser storage
  resets the pipeline to empty and the A/B store to the 23-entry mock seed.
